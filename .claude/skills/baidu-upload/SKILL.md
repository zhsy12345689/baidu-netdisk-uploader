# 百度网盘上传

用仓库根目录的 `bdupload.sh` 完成上传。它封装了 BaiduPCS-Go，补上排除规则、
预演、tmux 后台、登录预检和结构化日志。

## 安全红线（最重要，先读这条）

**绝对不要让用户把 BDUSS 或 STOKEN 贴进对话。** 这两个 cookie 等同于账号密码，
拿到就能读、写、删对方整个网盘。贴进对话就会永久留在会话记录里。

- 登录命令**必须由用户在自己的终端执行**，你只提供命令模板，让用户自己替换占位符。
- 不要用 Bash 工具代替用户执行 `login`，哪怕用户主动把值发过来了。
- **如果用户已经贴了**：直接告诉他这个凭证按已泄露处理，等当前任务跑完，
  去浏览器对百度账号执行一次「退出登录」（会作废所有已签发的 BDUSS）。
  不要现在就让他撤销 —— 那会把正在跑的上传一起打断。
- 不要把凭证写进任何文件、脚本或环境变量。

## 标准流程

### 1. 确认工具就位

```bash
ls bin/BaiduPCS-Go 2>/dev/null || ./install.sh
```

`install.sh` 会自动探测平台、拉最新版 BaiduPCS-Go 到 `bin/`。

### 2. 确认登录态

```bash
./bin/BaiduPCS-Go who
./bin/BaiduPCS-Go quota
```

`who` 显示出真实用户名（不是 `uid: 0, 用户名: ` 空值）才算登录成功。
`quota` 用来核对剩余空间够不够装这次要传的量 —— 传到一半空间不够很难收拾。

没登录的话，给用户这段（**让他自己跑**）：

```bash
./bin/BaiduPCS-Go login -bduss="你的BDUSS" -stoken="你的STOKEN"
```

取值方法：浏览器登录 pan.baidu.com 并**停在网盘页面** → F12 → Application →
Cookies → `https://pan.baidu.com` → 分别点中 `BDUSS` 和 `STOKEN` 两行，
从表格下方的 Value 面板复制完整值。

两个坑要主动提醒：

- **别从表格单元格里拖选**，长值显示不全会被截断。要点中行、从下方 Value 面板复制。
- **STOKEN 只挂在 `pan.baidu.com` 域下**，当前页如果是 `www.baidu.com` 就看不到它。
- BDUSS 是 HttpOnly，Console 里 `document.cookie` 读不到，只能走 Application 面板。

### 3. 先预演

**每次换新的源目录都要先跑这步**，别跳过。

```bash
./bdupload.sh -s <源路径> -d <网盘目录> [-x 排除规则] -n
```

预演不需要二进制也不需要登录，输出是「将要上传哪些项、各自多大、落到哪」。
拿这个跟用户确认两件事：

- 排除规则对不对（缓存目录、`.git`、临时文件、checkpoint 碎片有没有漏掉）
- 路径映射对不对 —— 源是目录时上传的是它的**内容**，
  `-s ./mydata -d /backup/mydata` 得到 `/backup/mydata/<mydata里的东西>`，不会双层嵌套

### 4. 正式上传

大任务一律走 tmux，避免断连中断：

```bash
./bdupload.sh -s <源路径> -d <网盘目录> [-x ...] -T <会话名>
```

超过几个 G 就该用 `-T`。之后 `tmux attach -t <会话名>` 看实时进度，
`Ctrl-B` 松开再按 `D` 退出看板（上传继续）。

### 5. 监控进度

日志默认在 `./<网盘目录名>_upload.log`。

```bash
echo "完成 $(grep -c '上传文件成功\|秒传成功' <日志>) / <总数>"
grep '上传文件成功\|秒传成功' <日志> | grep -o '<目录名>/[A-Za-z]*/' | sort | uniq -c
```

总数用 `find <源> -type f -not -path '*/<排除项>/*' | wc -l` 算。

**判读进度时注意**：按文件数算的百分比常常严重高估。如果大文件集中在队列末尾
（比如视频目录排在最后），文件数到 60% 时字节数可能才 20%。给用户估时要按
**字节**算，并说明依据。

### 6. 核对完整性

跑完必须核对，不能只看退出码 —— 有可能部分文件静默失败。

```bash
./bin/BaiduPCS-Go ls <网盘目录>              # 逐级核对目录结构和文件数
grep -c '上传文件失败\|错误' <日志>           # 应为 0
```

本地文件数和网盘文件数逐目录对上，才算完成。对不上就重跑同一条命令 ——
`--policy skip` 会跳过已传完的，只补缺失的。

## 常见故障

**`获取用户uk错误, 请确保登录信息包含了STOKEN`**
登录时只给了 BDUSS，漏了 STOKEN。症状具有迷惑性：`who` 和 `quota` 都正常
（BDUSS 足够查账号信息），但每个文件都卡在「开始计算文件元信息」后失败。
带 STOKEN 重新登录一次即可。报错里跟着的「或更换保存路径」是百度的通用文案，
跟路径无关，别被带偏。

**`秒传成功`**
正常现象，不是错误。百度服务器上已存在相同哈希的文件，直接引用，不消耗流量。
公开数据集命中率往往很高，会让实际耗时远低于按体积的估算。

**上传中断**
原样重跑同一条命令。默认 `--policy skip` 会跳过网盘上已有的同名文件。

**速度慢或停滞**
百度对上传通常不怎么限速（实测可到 ~11 MB/s），但长时间大流量后可能降速。
可以调 `-p`（单文件线程数）和 `-l`（并发文件数），但调太高容易触发风控，
默认的 `-p 4 -l 3` 是比较稳的档位。

**大量视频文件**
百度网盘对视频有自动审核，偶尔会误伤。被拦的话可以先 `tar` 打包再传。

**单文件超过 4G**
普通用户单文件上限 4G，SVIP 是 20G。超了要先切分（`split -b 3G`）。
预演输出里留意有没有超限的大文件。

## 合规提醒

上传第三方数据集前，确认许可证允许再分发。常见情况：

- CC BY-NC-SA / CC BY 等：允许分享，但要保留署名、注明许可证、不得商用（NC）
- 私人备份基本都没问题，**公开分享链接**才涉及再分发条款
- 数据里如果含人脸、声音等个人信息，别扩散到公开渠道

建议在上传目录里放一个 `LICENSE-AND-ATTRIBUTION.txt`，写清来源、作者、
许可证全名和链接、引用格式。以后分享给谁，署名条件都是齐的。
